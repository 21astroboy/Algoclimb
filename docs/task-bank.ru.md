# Как создавать банк задач

[Русский](task-bank.ru.md) · [English](task-bank.md) · [README на русском](../README.ru.md)

Банк — это JSON-файл в UTF-8 с **массивом объектов задач**. Условия, варианты и разборы
можно писать на русском, английском или другом языке: приложение их не переводит.
Для любого предмета подходят `choice` и `blank`; для графов и алгоритмов есть
интерактивные `graph`, `order` и `sort`.

## Файлы и загрузка

Рабочий банк храните в `secrets/task-bank.json`, разборы — в
`secrets/explanations.json`. В Docker они подключаются отдельным томом. После изменения
банка перезапустите или пересоберите приложение. Закрытые банки, ответы и ключи
сервисных аккаунтов не должны попадать в Git.

Порядок поиска банка: `TASK_BANK_PATH`, `secrets/task-bank.json`,
`backend/data/task-bank.json`, затем открытый `backend/data/task-bank.example.json`.
Для разборов: `EXPLANATIONS_PATH`, затем `secrets/explanations.json` или
`backend/data/explanations.json`. Ошибка в найденном JSON не означает автоматический
переход на следующий файл — проверяйте синтаксис перед запуском.

## Общие поля

| Поле | Назначение |
| --- | --- |
| `id` | Уникальная постоянная строка; связывает задачу, ответ и разбор. |
| `type` | `choice`, `graph`, `order`, `sort` или `blank`. |
| `title` | Короткое название в конструкторе сессии. |
| `prompt` | Условие: точно укажите, что должен отправить студент. |
| `topic` | Произвольная тема; по ней строится фильтр. |
| `level` | Сложность 1–3; влияет на баллы за верный ответ. |
| `timeLimit` | Необязательный положительный лимит в секундах, перекрывает лимит типа. |
| `block` | Необязательный набор задач для повторного использования. |
| `hint` | Необязательная авторская подсказка; используется и в части описаний ответов. Важные указания пишите в `prompt`. |
| `figure` | Необязательная строка с SVG над условием; используйте доверенный контент. |

Каждый пример ниже — отдельный объект. Для полного банка заключите объекты в `[` и `]`
и разделите запятыми. JSON не поддерживает комментарии и запятую после последнего элемента.

## 1. Выбор одного ответа — `choice`

Студент нажимает **один** вариант. `answer` — индекс правильного варианта **с нуля**
в исходном банке. Во время раунда варианты перемешиваются. Выбор нескольких ответов
этот тип не поддерживает.

```json
{
  "id": "demo_stack",
  "type": "choice",
  "topic": "asd",
  "level": 1,
  "title": "Стек",
  "prompt": "Какой принцип работы у стека?",
  "options": [
    "FIFO — первый вошёл, первый вышел",
    "LIFO — последний вошёл, первый вышел",
    "Случайный доступ по индексу",
    "Сортировка при вставке"
  ],
  "answer": 1
}
```

В примере верный индекс `1`: LIFO. Такой тип подходит для определений, оценки
сложности, комбинаторных подсчётов и чтения небольшого фрагмента кода. Неверный ответ
корректного формата расходует попытку, а некорректный формат — нет.

## 2. Построение или выбор рёбер графа — `graph`

### Точный набор рёбер

Студент соединяет вершины жестами. Итоговый набор должен совпасть с `requiredEdges`.
Порядок рёбер и направление записи пары не важны: графы **неориентированные**.
Лишние рёбра не допускаются. У треугольника это A–B, B–C и A–C.

```json
{
  "id": "demo_triangle",
  "type": "graph",
  "topic": "graphs",
  "level": 1,
  "title": "Постройте треугольник",
  "prompt": "Постройте граф-треугольник на вершинах A, B, C (каждая соединена с каждой).",
  "nodes": [
    "A",
    "B",
    "C"
  ],
  "requiredEdges": [
    [
      "A",
      "B"
    ],
    [
      "B",
      "C"
    ],
    [
      "A",
      "C"
    ]
  ]
}
```

### Любой граф с заданным свойством

Если верных конструкций несколько, задайте `graphKind` вместо `requiredEdges`.
Поле `example` показывает один пример для ключа ответов, но **не ограничивает**
проверку этим конкретным графом.

```json
{
  "id": "demo_tree4",
  "type": "graph",
  "topic": "graphs",
  "level": 2,
  "title": "Любое дерево на 4 вершинах",
  "prompt": "Постройте любое дерево на вершинах A, B, C, D (связный граф без циклов, ровно 3 ребра).",
  "hint": "Дерево из n вершин имеет ровно n−1 ребро и не содержит циклов.",
  "nodes": [
    "A",
    "B",
    "C",
    "D"
  ],
  "graphKind": "anyTree",
  "example": [
    [
      "A",
      "B"
    ],
    [
      "B",
      "C"
    ],
    [
      "C",
      "D"
    ]
  ]
}
```

Для `anyTree` подходят и путь A–B–C–D, и звезда с рёбрами A–B, A–C, A–D.

| `graphKind` | Что принимает текущая проверка | `graphArg` |
| --- | --- | --- |
| `anyTree` | Связный граф с n−1 рёбрами. | — |
| `anyPath` | Связный путь через все вершины. | — |
| `anyCycle` | Связный цикл через все вершины. | — |
| `anyComplete` | Каждая пара вершин соединена. | — |
| `anyCompleteBipartite` | Связный полный двудольный граф с двумя непустыми долями. | — |
| `anyComponents` | Ровно k компонент **без изолированных вершин**. | k |
| `anyBinaryTree` | Дерево с максимальной степенью 3; корень и направления к детям не проверяются. | — |
| `anyCycleChord` | Связный граф с n+1 рёбрами, двумя вершинами степени 3 и остальными степени 2. | — |
| `anyEulerian` | Связный граф с положительной чётной степенью каждой вершины. | — |
| `anyStar` | Звезда на всех заданных вершинах. | — |
| `anyForest` | Лес с k компонентами; изолированные вершины допустимы. | k |
| `anyRegular` | Связный k-регулярный граф. | k |

Графы простые, неориентированные. Используйте разные метки вершин.
`anyBinaryTree` не проверяет двоичное дерево поиска с корнем, а `anyCycleChord`
проверяет перечисленные степени и число рёбер, без отдельного поиска гамильтонова цикла.

### Минимальное остовное дерево

При `weighted: true` и наличии `refEdges` студент выбирает рёбра из готового
взвешенного графа. Ребро задаётся как `[откуда, куда, вес]`. Принимается остов
минимального суммарного веса; разные минимальные остовы могут быть верными.

```json
{
  "id": "mst_triangle",
  "type": "graph",
  "topic": "graphs",
  "level": 2,
  "title": "Минимальное остовное дерево",
  "prompt": "Выберите минимальный остов взвешенного графа.",
  "nodes": [
    "A",
    "B",
    "C"
  ],
  "weighted": true,
  "refEdges": [
    [
      "A",
      "B",
      2
    ],
    [
      "B",
      "C",
      3
    ],
    [
      "A",
      "C",
      8
    ]
  ]
}
```

В этом примере рёбра A–B и B–C дают минимальный вес **5**. Ребро A–C слишком дорогое.
Исходный граф должен быть связным. Для задачи на минимальный остов не задавайте `requiredEdges`.

## 3. Порядок обхода — `order`

Студент нажимает вершины в порядке посещения. Задайте `nodes`, неориентированные
`edges`, стартовую вершину `start` и `mode: "bfs"` или `"dfs"`. Каждая вершина должна
встретиться ровно один раз, первой — `start`. Используйте связный граф: проверка
ожидает единый обход всех заданных вершин.

```json
{
  "id": "demo_bfs",
  "type": "order",
  "topic": "graphs",
  "level": 1,
  "title": "Обход в ширину (BFS)",
  "prompt": "Выполните обход в ширину (BFS) из вершины A. Кликайте вершины в порядке посещения.",
  "hint": "BFS: сначала стартовая вершина, затем все её соседи, затем соседи соседей (очередь).",
  "nodes": [
    "A",
    "B",
    "C",
    "D",
    "E"
  ],
  "edges": [
    [
      "A",
      "B"
    ],
    [
      "A",
      "C"
    ],
    [
      "B",
      "D"
    ],
    [
      "C",
      "D"
    ],
    [
      "C",
      "E"
    ]
  ],
  "start": "A",
  "mode": "bfs"
}
```

Для BFS верны **A → B → C → D → E** и **A → C → B → D → E**: порядок соседей
не фиксирован. Проверяется корректность обхода, а не совпадение с одной записанной
последовательностью. Для DFS также допустимы разные соседи, но нельзя возвращаться
по стеку, пока у текущей вершины остались непосещённые соседи.

Не требуйте в условии обязательного алфавитного порядка без доработки проверки:
сейчас другие корректные порядки соседей тоже принимаются.

## 4. Шаги сортировки — `sort`

Студент переставляет числа и отправляет состояние массива **после указанного числа
шагов**, а не обязательно полностью отсортированный массив.

```json
{
  "id": "demo_bubble",
  "type": "sort",
  "topic": "asd",
  "level": 1,
  "title": "Пузырьковая сортировка: 1 проход",
  "prompt": "Расставьте элементы так, как массив будет выглядеть после ОДНОГО прохода пузырьковой сортировки (по возрастанию).",
  "hint": "За один проход соседи сравниваются слева направо; наибольший элемент «всплывает» в конец.",
  "array": [
    5,
    2,
    8,
    1,
    9,
    3
  ],
  "algo": "bubble",
  "steps": 1,
  "expected": [
    2,
    5,
    1,
    8,
    3,
    9
  ]
}
```

Один проход пузырьковой сортировки слева направо превращает `[5, 2, 8, 1, 9, 3]`
в **`[2, 5, 1, 8, 3, 9]`**. Полностью отсортированный массив здесь будет неверным ответом.

- `algo: "bubble"`: шаг — проход слева направо по оставшейся неотсортированной части.
- `algo: "insertion"`: шаг — вставка очередного элемента в отсортированный префикс.
  Для `[4, 1, 3, 2]` после одного шага будет `[1, 4, 3, 2]`, после двух — `[1, 3, 4, 2]`.
- `steps` — число проходов или вставок; `expected` — точное итоговое состояние массива.
  В ручном банке укажите `expected`: именно с ним сравнивается ответ.
- При `paramize.enabled: true` сервер может сгенерировать новый массив и пересчитать
  `expected` для сессии. Для воспроизводимых авторских примеров установите `false`.

## 5. Заполнение пропусков — `blank`

Каждое `___` в `template` превращается в поле, соответствующее очередному элементу
`blanks`. Если есть `options`, появляется список; иначе — свободный ввод.

```json
{
  "id": "demo_blank",
  "type": "blank",
  "topic": "asd",
  "level": 1,
  "title": "Заполните пропуски: стек",
  "prompt": "Дополните описание стека.",
  "template": "Стек работает по принципу ___. Операция ___ добавляет элемент.",
  "blanks": [
    {
      "answer": "LIFO",
      "alts": [
        "последний вошёл — первый вышел"
      ]
    },
    {
      "answer": "push",
      "options": [
        "push",
        "pop",
        "peek"
      ]
    }
  ]
}
```

Верная пара — **LIFO, push**. Все пропуски должны быть верными: частичных баллов
за отдельные поля нет.

При свободном вводе регистр не важен, лишние пробелы по краям убираются, повторные
пробелы нормализуются. `alts` добавляет допустимые варианты: нечёткого сравнения
и исполнения введённого кода нет. Для списка сравниваются точные строки вариантов.
Значение `answer` должно входить в `options`, число `___` — совпадать с длиной `blanks`.

Пример для комбинаторики: `"Число перестановок трёх объектов равно ___."`
с `"blanks": [{"answer": "6", "alts": ["3!", "шесть"]}]`.

## Иллюстрации, формулы и разборы

В условиях можно использовать `$...$` и `$$...$$` для KaTeX, например
`"Сколько рёбер у $K_5$?"`. В `figure` можно передать строку SVG с `viewBox`,
например диаграмму Венна. Внутренние двойные кавычки экранируйте по правилам JSON.
Иллюстрация поясняет условие, но сама не задаёт правила проверки.

Разборы хранятся отдельно, ключ — ID задачи:

```json
{
  "demo_stack": "Стек сначала извлекает последний добавленный элемент.",
  "demo_triangle": "У трёх вершин три неупорядоченные пары, поэтому нужны три ребра."
}
```

Они появляются в личном разборе студента после завершения сессии. Банк с ответами
и разборы должны оставаться на сервере, а не в публичных файлах frontend.

## Перед занятием с новым банком

1. Проверьте синтаксис: `python -m json.tool secrets/task-bank.json > /dev/null`.
2. Проверьте уникальность ID, типы, вершины, индексы правильных вариантов и число пропусков.
3. Сопоставьте условие с правилами проверки выше. Явно укажите стартовую вершину,
   число шагов сортировки или нужное свойство графа.
4. Перезапустите приложение, выберите задачи и проведите **Practice**-сессию с телефона.
5. Отправьте верный и неверный ответы, посмотрите ключ преподавателя и финальный разбор.

Проверка JSON подтверждает только синтаксис, а не всю схему задач. Рабочие примеры:
[открытый демобанк](../backend/data/task-bank.example.json) и
[русский набор для скриншотов](../tools/fixtures/screenshot-bank.ru.json).
