# AlgoClimb

Локальное веб-приложение для интерактивных лекций по «Алгоритмам и структурам данных» и «Теории графов».
Лобби с никами и иконками, интерактивные задачи (включая построение графа мышью/пальцем), гора прогресса
с лидербордом, множители баллов за финиш и автоматическая отметка посещаемости.

Это **первая рабочая версия (MVP)**. Контроль присутствия по сети пока выключен — приложение запускается в любой сети.

---

## Требования

- **Node.js 22 или новее** (нужен встроенный модуль `node:sqlite` — без него данные пишутся в JSON-файлы как запасной вариант).
  Проверить: `node --version`. Если меньше 22 — обнови с https://nodejs.org

## Запуск

```bash
cd algoclimb
npm install      # ставит ws + qrcode, нативной сборки нет
npm start
```

В консоли появятся адреса:

```
  Преподаватель:  http://localhost:3000/teacher
  Студенты:       http://192.168.x.x:3000/      <- этот адрес зашит в QR
```

- **Со своего ноута** открой `http://localhost:3000/teacher` — это экран для проектора (лобби, QR, гора).
- **Студенты** сканируют QR на проекторе или открывают адрес `http://192.168.x.x:3000/`.
  Адрес работает, только если телефон в той же сети, что и ноут.

## Правильные ответы (только для преподавателя)

Два способа посмотреть верные ответы:

- **Кнопка «👁 Показать ответ»** на экране `/teacher` — показывает ответ на текущий вопрос.
  Внимание: экран идёт на проектор, поэтому ответ увидят и студенты. Жми только когда нужно разобрать вопрос.
- **Ключ ответов `http://localhost:3000/answers`** (кнопка «🔑 Ключ ответов» в шапке `/teacher`) —
  приватная страница со всеми вопросами и ответами, с поиском и фильтрами. Открывай её на своём
  ноуте/телефоне; во время игры она подсвечивает текущий вопрос. Ответы передаются только этой
  странице и экрану преподавателя — студентам они не уходят.

  Замечание про доступ: как и весь интерфейс преподавателя, страница не требует пароля — любой в той же
  сети, кто знает адрес `/answers`, теоретически может её открыть. Не давай этот адрес студентам;
  при необходимости включи `ipAllowlist` в `config.json`.

## Запуск через Docker (без установки Node)

Если Node ставить не хочется — есть `Dockerfile` и `docker-compose.yml`.

```bash
cd algoclimb
HOST_IP=$(ipconfig getifaddr en0) docker compose up --build
```

`HOST_IP` — адрес ноута в сети вуза, он попадёт в QR-код для студентов.
**Это обязательно**: без него QR покажет внутренний IP контейнера и телефоны не подключатся.
Узнать адрес вручную: macOS — `ipconfig getifaddr en0` (Wi-Fi) или System Settings → Wi-Fi → Details.

Остановить — `docker compose down`. База и журналы лежат в `./data` (том), переживают перезапуск.

## Как идёт сессия

Модель **синхронная**: весь класс отвечает на один и тот же вопрос одновременно.

1. Преподаватель открывает `/teacher`. На экране — QR и лобби.
2. Студенты заходят, вводят ник (выданный заранее), выбирают иконку → попадают в лобби.
   В этот момент фиксируется **посещаемость**.
3. Преподаватель жмёт **Старт** — лобби закрывается, всем выдаётся первый вопрос.
4. На каждый вопрос идёт **таймер** (по умолчанию выбор — 10 с, построение графа — 25 с).
   Раунд закрывается, когда **все ответили** ИЛИ **истёк таймер** — тогда автоматически
   выдаётся следующий вопрос. На один вопрос — **одна попытка**.
5. Очки: за верный ответ начисляется `база × сложность × скорость` (чем быстрее — тем больше);
   неверный ответ или отсутствие ответа — 0. Варианты ответа каждый раунд перемешиваются,
   чтобы верный не «прилипал» к первой позиции.
6. На экране преподавателя: гора прогресса, живой лидерборд по очкам, счётчик ответивших,
   сколько раз каждый **уходил со вкладки** (⚠), и кнопка **выгнать** студента (✕).
7. Преподаватель жмёт **Завершить** — показываются итоги: лидерборд по очкам и
   статистика ответов «как в биатлоне» (зелёный кружок — верно, красный — неверно,
   серый — без ответа). Всё пишется в базу.
8. **Сброс** — начать новую сессию (новое лобби).

## Где лежат данные

`algoclimb/data/algoclimb.db` (SQLite) — таблицы `attendance`, `answers`, `results`, `events`, `sessions`.
Если Node старый и SQLite недоступен — те же данные в `data/*.jsonl`.

## Настройки — `config.json`

```jsonc
{
  "port": 3000,
  "stream": 2,                 // номер потока (попадает в записи посещаемости)

  // Демо-режим: на сессию берётся не весь банк, а несколько случайных задач.
  "demo": { "enabled": true, "count": 5, "onePerType": true },

  // Время на вопрос (секунды): choice — выбор варианта, graph — построение графа.
  "timeLimits": { "choice": 10, "graph": 25 },

  // Очки = base × сложность(1..3) × (minFraction + (1−minFraction)×доля_оставшегося_времени).
  "scoring": { "base": 100, "minFraction": 0.4 },

  "revealMs": 1800,            // пауза между вопросами (мс), чтобы увидеть результат

  "activeTasks": [],           // пусто = весь банк; иначе перечисли id нужных задач

  "ipAllowlist": {             // пускать только из сети вуза
    "enabled": false,          // включишь, когда проверишь сеть
    "cidrs": ["192.168.0.0/16", "10.0.0.0/8"]
  },
  "qrRotation": {              // код в QR меняется каждые N секунд
    "enabled": false,
    "intervalSec": 8
  }
}
```

- **demo** — для лекции-демонстрации берём `count` случайных задач. `onePerType: true` гарантирует хотя бы по одной задаче каждого типа (выбор/построение). Выключи (`"enabled": false`), чтобы использовать весь банк.
- **timeLimits** — лимит времени на вопрос; от оставшегося времени зависят очки.
- **scoring** — `base` — базовые очки, `minFraction` — доля очков даже за ответ в последнюю секунду (0.4 = минимум 40%); `streakStep` — бонус за каждый верный ответ подряд начиная со 2-го; `streakMax` — потолок бонуса за серию.
- **ipAllowlist** — когда включишь, студенты вне указанных диапазонов получат отказ. Локальный экран преподавателя (127.0.0.1) всегда разрешён.
- **qrRotation** — при включении студенту нужно ввести 6-значный код с экрана (он меняется), что мешает заходить «из дома».

## Задачи — `tasks.js`

Банк задач. Каждая знает, как проверить ответ на сервере (правильные ответы клиенту не уходят).
Типы: `choice` (один вариант) и `graph` (построить граф — порядок и направление рёбер не важны).
У каждой задачи есть `id`, `topic` (`asd` / `graphs`) и `level` (1–3).

Сейчас в банке ~98 задач: по алгоритмам и структурам данных (сложности, стек/очередь/куча,
сортировки, хеш-таблицы) и по теории графов (BFS/DFS, деревья, Дейкстра, остовное дерево,
топосортировка, двудольность, Эйлеров цикл) плюс интерактивные построения графа
(цикл, путь, звезда, K₄, K₂,₃, дерево).
Варианты ответа сервер перемешивает на каждый раунд, поэтому верный ответ равномерно
распределён по позициям (не «всегда первый»).

**Выбор задач на конкретную лекцию** — в `config.json` поле `activeTasks`:

```jsonc
"activeTasks": []                                  // пусто = все задачи по порядку
"activeTasks": ["gr_bfs", "gb_cycle4", "asd_heap_min"]   // только эти три, в этом порядке
```

Добавляй свои задачи по образцу в `tasks.js`.

## Что нового в этой версии

- **Объяснения после игры**: каждому студенту в конце показывается разбор всех вопросов
  с правильным ответом и кратким объяснением (поле в `explanations.js`, по задаче на id).
- **Бонус за скорость и серию**: студент видит вклад скорости (`⚡`) и бонус за серию верных
  подряд (`🔥`). Формула очков: `база × сложность × minFraction` (гарантия) `+` вклад скорости
  `+` бонус за серию (`streakStep` за каждый верный начиная со 2-го, потолок `streakMax`).
- **Аналитика** (кнопка «📊 Аналитика» на экране преподавателя): история всех сессий
  (участники, точность, средний балл) и статистика по каждой задаче (попытки, точность,
  среднее время) с сортировкой «сложные сверху» — видно, какие вопросы стабильно проваливают.
- **Восстановление сессии у преподавателя**: при разрыве связи вкладка сама переподключается
  и подхватывает текущее состояние (всё хранится на сервере).
- **Подсказки у студентов убраны** (в графовых задачах): остаются только у преподавателя.
- **Синхронная игра**: весь класс на одном вопросе, переход — когда все ответили или вышло время.
- **Таймеры** на каждый вопрос (выбор 10 с / граф 25 с, настраивается).
- **Очки** за скорость и сложность; неверный ответ — 0; одна попытка на вопрос.
- **Демо-режим**: на сессию берётся 5 случайных задач (хотя бы по одной каждого типа).
- Варианты ответа **перемешиваются** каждый раунд (верный не «прилипает» к первой позиции).
- У студента **подсвечивается** его неверный ответ (красным), верный — зелёным.
- У преподавателя: **кик** студента, счётчик **уходов со вкладки**, итоги с
  **биатлонными кружками** (зелёный/красный/серый) по каждому вопросу.

## Что осознанно НЕ сделано (следующие шаги)

- Выгрузка результатов в Google Sheets (пока данные в SQLite; экспорт — отдельный шаг).
- Конструктор задач через интерфейс (сейчас задачи правятся в `tasks.js`).
- Проверка изоляции клиентов в сети вуза → выбор сценария размещения (см. дизайн-документ).
- Больше типов интерактивных заданий (обходы DFS/BFS, остовное дерево, операции со структурами).
- Более богатая анти-ИИ телеметрия (сейчас ловится только уход со вкладки).
